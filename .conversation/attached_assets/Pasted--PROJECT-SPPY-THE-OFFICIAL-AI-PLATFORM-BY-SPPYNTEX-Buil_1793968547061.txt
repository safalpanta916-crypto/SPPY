This is a critical requirement.

SPPY must connect to a genuine AI model through a secure server-side API.

Do not create a fake chatbot using hardcoded responses.

Build a provider-independent AI service architecture.

Requirements:

- Secure server-side API calls.
- Environment-variable-based API configuration.
- Streaming responses where supported.
- Conversation context.
- Mode-specific system prompts.
- Error handling.
- Request timeouts.
- Token or output limits.
- Appropriate response formatting.
- Graceful handling of unavailable providers.
- Easy future model/provider replacement.

Keep provider-specific logic separate from the frontend.

Use an environment variable such as:

AI_API_KEY=

Also support configurable:
- AI_API_BASE_URL
- AI_MODEL

Do not expose secrets through frontend JavaScript, public configuration files, GitHub commits, or browser network responses.

Provide an example environment file containing placeholders only.

If credentials are unavailable during development, build the complete integration and a clear setup state explaining that the AI provider needs configuration.

Do not claim the platform is fully operational until a real API key has been configured and tested.

The AI backend should be designed so additional providers can be added without rewriting the application.
